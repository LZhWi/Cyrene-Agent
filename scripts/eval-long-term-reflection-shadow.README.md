# 长期观察 Shadow V3（独立、只读）

本脚本不接入正式回复、画像更新、记忆写入或定时任务。它只导入纯函数和供应商请求适配器；真实数据只读，模型输出保留在项目同级的 `Cyrene-Shadow-Reports/long-term-v2-*`。

## 运行

从 Cyrene-Agent 项目根目录运行，先退出 Cyrene，避免正式程序并发更新使源文件校验失效：

```powershell
npm.cmd run build:main
node scripts/eval-long-term-reflection-shadow.mjs
```

默认只准备证据，不调用模型，不伪造观察结果。实时小规模测试使用现有主模型配置：

```powershell
node scripts/eval-long-term-reflection-shadow.mjs --live-llm --reply-ab
```

若 0.85 阈值没有候选，可显式运行独立的 0.80 召回对照：

```powershell
node scripts/eval-long-term-reflection-shadow.mjs --explore-recall --live-llm --reply-ab
```

这不会修改正式检索阈值。报告同时保留 0.85 基线；不能把降低阈值后的结果伪称原基线结果。最多 7 次请求（生成、训练语义审查、留出审计及四次回复），无自动重试，单次超时 300 秒。Windows 下会在调用前检查本项目 Electron 主进程，发现仍在运行就拒绝测试；打包版及其他写入者仍需自行退出，最终哈希检查不能省略。请求使用现有主模型 API；报告目录含私人聊天快照、引用和回复，请勿上传。

V3 的 `--reply-ab` 默认只导出 `reply-candidates.json`，不自动调用回复模型。要实际比较，额外传 `--reply-cases <人工审阅的JSON路径>`。文件必须包含两条记录，分别为 `positive` 与 `control`，字段是 `messageKey`、`label`、`observationKeys`、`reason`。消息必须属于真实留出窗口，观察键必须匹配本次语义审查通过的候选。模型生成键可能变化，不匹配时会失败，不能偷偷替换成其他观察。没有正例就不要构造该文件。报告目录沿用 `long-term-v2-*` 前缀，报告内 `version: 3` 区分版本。

语义门控回归可使用 `--live-llm --semantic-fixtures <JSON路径>`（不能同时 `--reply-ab`）。文件含 `observations` 及 `expectedAcceptedKeys`；观察仍必须引用本轮核验过的训练来源。此模式跳过自然生成和留出审计，只调用一次训练语义审查。预期键不会发送给模型，报告以 `semanticFixtureRun` 标注，结果不能算作自然发现或回复收益。用于同时验证有依据的窄结论能够通过、过度概括会被拒绝。

## 校验和边界

- 只有来源时间附近能唯一匹配实际用户原文的记忆才可作为证据；仅时间接近不算匹配。多段引用必须全部匹配，AI 发言不算用户证据。
- 排除失效、替代、过期、未解决冲突的记忆；压缩总结不作独立证据。同一来源消息重叠时保守保留最早记录，可能牺牲召回。
- 训练证据的来源时间、写入时间均须早于最近 14 天留出窗口；至少 3 条、3 个来源日期、14 天跨度。现存记录仍存在回溯样本偏差，不能宣称真实历史数据库重放。
- 候选最多 3 条，要求窄结论和适用范围；证据高度重合的观察暂缓，不自动合并语义。留出审计漏项、重复、非法引用会失败。
- 生成后独立审查训练证据：每段支持引文必须支持完整单一断言；模型审查通过后，代码还会检查原文一致、至少三条三日期十四天和无来源重叠。漏审、复合断言、假引文或仅一条直接证据不能通过。语义审查本身仍由同一模型提供，不能当作人工真值。
- A/B 固定相同模型、人格提示、16 条近期消息、5 条记忆与 3 条历史候选；只在一个分支加长期观察。使用事先明确标注的真实正例及对照例，不使用留出审计结果挑选观察。
- A/B 是文本提示对照，不是正式混合检索、RRF、reranker、工具调用链的端到端评测；两对回复不能证明总体提升。
- “最相关”只是候选池中的向量排名，不保证它是需要长期观察的正例。必须人工核对问题与观察是否真正相关；缺少正例时只能评估无关上下文干扰，不能宣称验证了收益。
- 先审阅 `reply-comparison.json` 的匿名 A/B，再查看 `blind-key.json`。不要把同一主模型的审计当作独立人工真值。
- 所有结果留档；错误、空响应、截断、超时不是成功。源数据目录、聊天索引/会话、向量库的 JSON 文件清单及 SHA-256 前后必须相同，否则本轮隔离验证失败。

`report.json` 是总报告，`evidence.json` 包含入选/排除原因，`observations.json` 包含观察及去重结果，`*-input/output.json` 用于核对实际模型输入输出。API 密钥不写入报告。
