# Cyrene 本地插件开发基座

实施顺序和暂缓事项见 [TODO.md](TODO.md)。当前只在上游原生 Chat 中复现本地 `Cyrene-Agent`
的聊天、人格与记忆行为；Work、Code、Learn、朋友圈和外部渠道不属于当前验收范围。新的记忆

剩余限制见 [原生 Chat 自动化对照](NATIVE-CHAT-AUTOMATION-AUDIT.md)。

## 目录约定

```text
local-plugins/
  plugins/<plugin-id>/
    manifest.json
    README.md
    src/index.ts
    static/          # 可选；原样复制到插件包根目录
  tests/             # SDK 与公共契约兼容测试
  scripts/build.mjs  # 构建并生成可安装 ZIP
  artifacts/         # 本地产物，不进入 Git
```

每个插件都必须只依赖官方 SDK 的公开类型和接口，不得导入 Cyrene 的 `src/main/**`、
`src/renderer/**` 或 `src/shared/**`。

## 独立聊天与记忆迁移

新增 `companion-chat` / `companion-memory` 两个隔离开发插件，公用源码在 `plugins/shared/`，
构建时分别打包进插件，不产生宿主私有依赖。模型入口支持复用当前宿主、只读原模型配置、自定义模型。
原模型文件与凭据均不复制；默认使用当前宿主官方模型服务，只有用户主动选择时才只读另一配置文件。

当前同时支持独立聊天闭环，以及基于官方 `host:turn:finished`、冻结消息边界和
Prompt Provider 的原生桌面聊天接入。读取、宿主模型自动提取和原生回复注入分别授权且默认关闭。
另有手动确认的 2+10 分层证据提取。记忆插件 0.50.0 已提供 L0/L1/L2、画像锁定与编辑、
L1 新鲜期、L2 编辑/置顶/归档、迁移备份，以及默认关闭的独立 Embedding Provider 与旧 user_memory
向量索引迁移、Reranker、DMAE、人工生命周期候选、维护候选收件箱、可撤销压缩和人工梦境反思。
后台候选复核可在单独授权后每 5 个成功桌面 Chat 轮次处理一对收件箱候选；后台压缩可在另一项
授权后每 20 轮为一组合格 aging 向量候选生成建议。两类后台复核默认都只保存建议；只有用户分别
开启安全自动应用授权后才处理各自的严格白名单计划。压缩自动应用还要求至少 3 条 aging、非置顶、
非摘要来源、置信度至少 0.80 且明确确认完整覆盖，并在提交前重新核对全部记忆与证据快照。用户可在
“生成建议后手动确认”和“符合安全条件时自动压缩”之间明确选择；界面顶部显示最近 3 个压缩组。
每日生命周期扫描默认只保存两类候选数量；另行授权后，可把闲置 30 天的 active 和扫描前已闲置
90 天的 aging 记忆各最多 100 条原子地降一级，每组都保留可撤销快照。实际注入会在插件私有
生命周期状态中累积 0 至 100 的 weight，获授权的每日执行同时将有效非置顶项 weight 减 1；
容量页面可只读预检并逐次确认执行本地版 300/800 上限计划；执行绑定记忆与生命周期版本，分组最多 100 条并保留可撤销快照。归档记忆还可在普通有效记忆没有明确词面/分面命中时只读列为冷召回候选，只有用户选择确认后才恢复为 active，并保留严格撤销快照；候选不会自动注入或更新激活/访问状态。原生 Chat 近似空闲梦境
在 15 分钟无桌面 Chat 活动时按“容量降级 → 本轮降级项叙事 → aging 聚类压缩”运行完整周期，但不能读取系统级真实空闲状态；叙事保存与压缩应用继续分别授权，周期启用时暂停独立二十轮压缩计时；
双条复核已能保存本地版五类 Resolver 关系、置信度、澄清标记和结构化变更计划；用户确认后可原子
创建带双来源谱系的新总结并更新两侧状态，且支持严格撤销。
画像反思可在独立授权后每 20 轮用可逐字核对来源的插件私有 L2 生成待确认 L0/L1 变更；
建议保留来源快照，人工采用前重新核对并可严格撤销。不会照搬本地版缺少长期互动证据的直接覆盖，
也不会新增空字段或绕过 L0 锁定；仅凭模型自报置信度仍不开放语义自动采用。
不要把本版本当作本地记忆系统的等价替代。

L0/L1 同字段不同表述现在进入待确认列表，不自动覆盖旧值；界面支持保留当前值/采用候选，
保留新旧证据及处理记录，并防止过时候选覆盖后续编辑。此功能不等同于 L2 语义冲突识别。

L2 可手动选两条有效记忆，确认后请求当前宿主官方模型服务复核；只发送这两条摘要与证据，模型不自动
改记忆。新版结果可提出五类关系、完整合并总结和两侧状态计划；用户可保留现状、单独归档一侧，或
确认原子应用整份计划。计划保留快照与双来源谱系，在内容和证据没有后续变化时可严格撤销。
另有独立、默认关闭的安全自动应用授权：只处理置信度至少 0.90 的无变更结论，或带完整总结且
两侧均退出当前状态的偏好演进；直接冲突、证据不足、低置信和需澄清计划始终保留人工确认。
维护收件箱可本地发现正文重复/向量相似候选，并在用户确认后一次串行辅助复核最多 5 对；结果
仍只进入待确认列表。尚无后台自动冲突扫描，亦未验证真实模型的冲突判断质量。

L2 已支持老化/取代/合并状态和事实有效期、取代/合并关联的注入过滤，归档恢复不能清除这些约束。
用户可独立授权记录真正注入聊天的最后时间，再纯本地预检闲置至少 30 天的 active 非置顶候选；
只有选择并确认后才标为 aging，未命中不会被解释为内容错误。没有后台自动老化或自动归档。

独立 evidence 记录现已支持按 memoryId 关联检索、界面展示及复核快照，明确标注来源核验状态；
deleted 不注入，非活动摘要不因关联证据复活。旧 memory.json 已有“只读预检→源哈希复核→
空库备份→用户再次确认→单次状态提交”的生产导入入口；不会覆盖或自动合并非空插件库。
旧来源统一保留为未核对状态；facets已严格迁移并用于保守的清单查询补充。旧 user_memory 向量可在
记忆导入后单独预检并确认复制，chat_history 文本、DMAE、梦境及维护日志不迁移。

旧记忆可在插件窗口选择最多 20 个原生会话做只读 triggerText 来源核验。唯一匹配再次确认后
批量绑定；重复原文保留全部候选，可人工选择，或在单独确认后用当前宿主模型做两阶段语义推荐。
模型推荐不会直接写来源，最终消息 ID 绑定仍由用户确认。

语义检索使用插件自有 OpenAI-compatible Provider，因为官方 API v1 没有宿主 Embedding 依赖。
密钥只存官方 Secrets；启用 Provider 只授权发送当前查询。新提取/编辑记忆的摘要正文使用另一个
默认关闭的独立授权：启用后与本地版一致，自动为既有及发生变化的可检索 L2 摘要补齐当前
语义向量，不发送原话、证据或聊天历史。关闭后取消在途任务，失败保留待处理状态供明确重试。
旧索引和新生成索引可共存，但维度必须与 Provider 配置一致。诊断页仍可只读列出自动处理失败后
缺少当前向量的有效摘要，并由用户选择最多 100 条手动重试；预检后的内容或版本变化会使操作失效。

记忆窗口可选择开启模型辅助查询扩展（默认关闭、需确认）：只发送当前查询到当前宿主官方
模型服务，生成最多 3 个相关短语辅助本地召回。它增加模型请求、费用和延迟，失败明确报错；
扩展词不落入记忆、不直接注入回复。这不等同于向量检索，尚未做真实模型召回评测。

独立聊天和手动搜索还可单独启用模型候选重排：只发送当前查询和最多 12 条非置顶 L2 摘要，
使用临时编号并严格校验完整排列。置顶记忆保持最前且不外发；原生 Prompt Provider 不调用该模型，
避免宿主回复生成期间发生递归。默认关闭，尚未进行真实模型质量评测。

插件私有 DMAE 工作记忆也默认关闭。启用后仅在独立聊天或原生桌面对话实际构建记忆注入时更新
激活度，短暂驻留近期命中条目；手动搜索、预检、scheduler 和 channel 不改变激活值。DMAE 状态
独立存储，不回写宿主数据，也不更新原项目的 weight、lastRecalledAt 或其他访问统计。

人工梦境反思允许从 2 至 20 条 aging 非置顶记忆生成叙事草稿。模型请求、保存草稿和聊天注入
分别受用户操作/开关控制；持久化 ID 不发送给模型，叙事明确标为模型反思而不是事实证据，来源
记忆不被修改。保存后可撤销，注入默认关闭且只取最近 3 段。没有后台计时器或静默模型调用。

记忆窗口可纯本地预检高相似向量对，最多比较 300 条、显示 50 对。结果只用于填入现有双条复核，
不自动视为冲突或重复，不调用模型、不写索引，也不推进 DMAE；模型复核仍需用户另行确认。

旧压缩摘要现会保留 `subEntryIds`，并从叶子来源递归推导时间包络；缺失子项、循环或未解析叶子
会关闭导入门禁。历史消息只直接绑定叶子，全部叶子核验后才更新总结包络，且不会宣称总结语义
已被原话证明。

用户还可选择 2 至 5 条有效 L2 请求压缩建议，再次确认后才创建多来源总结并把原条目标记为
merged。原条目和证据不删除；在结果、来源和证据均未发生后续变化时可严格撤销，并清理新总结的
生成向量。这不是后台自动压缩或静默合并。

两个插件只通过官方 Storage/Secrets 写入各自私有数据，并校验真实存储根、直属状态文件和链接逃逸；
不会写入宿主原记忆、原会话或用户选择的只读源文件。本开发基座不会自动安装或启动正式宿主。
隔离宿主测试还覆盖市场 ZIP 替换和卸载：替换会重载插件并逐字节保留私有记忆；卸载会释放 IPC
等运行资源并删除插件程序目录，但按上游约定保留插件私有数据目录。

可选真实配置只读测试（不调用模型、不输出密钥；需有原文件读取权限）：

```powershell
$env:CYRENE_READONLY_MODEL_TEST = '1'
$env:CYRENE_READONLY_MODEL_PATH = 'C:\path\to\live2d-cyrene\model-settings.json'
.\node_modules\.bin\vitest.cmd run --config vitest.config.mjs tests/companion.test.ts
```

`.test-runtime/` 只放合成测试数据；真实配置只在内存解析并核对前后 SHA-256，不保存副本。

已增加真实 L2 只读隔离测试（默认跳过），方法、汇总及限制见 [READONLY-MEMORY-CHECK.md](READONLY-MEMORY-CHECK.md)。
测试不导入生产数据，不调用模型；词面自检通过不代表完整语义召回已达到原项目效果。

原始聊天只读核验已补 triggerText 的唯一逐字/规范化匹配，不依赖预存消息 ID；多条命中保留
候选与前后各一条上下文，无匹配时不自动认定来源。现存向量与时间候选可在明确授权后交由
模型定位和独立复核；真实快照7条中确认6条、1条保持未确认。该工具仍仅用于测试，结果未回填，
也未进入生产导入。

只读核验工具可使用现存 L2/聊天向量在内存中生成语义 Top 8，并严格回查正式用户消息；
不运行 Embedding 或正式 RAG，也不更新召回状态。它是候选生成，不是来源证明或生产检索能力。

只读核验工具已支持按完整 subEntryIds 推导压缩总结来源时间包络，缺失/未定位子项和循环不兜底猜测。
这不是摘要语义真实性证明，也不会写回原记忆的任何字段。

## 使用

首次安装依赖时，把 npm 缓存也限制在本目录：

```powershell
npm.cmd install --cache .npm-cache --no-audit --no-fund
```

完整验证：

```powershell
npm.cmd run verify
```

验证流程依次执行：

1. TypeScript 严格类型检查；
2. SDK API 版本、能力清单、稳定错误码兼容测试；
3. Manifest、插件注册、工具契约和停止清理测试；
4. 将每个插件构建为不依赖 SDK 运行时的 `index.cjs`；
5. 使用上游真实 `PluginManager` 在 `.test-runtime/` 验证仅聊天、仅记忆、显式联动三种隔离加载；
6. 对最终产物执行注册、依赖注入与停止清理冒烟测试；
7. 在 `artifacts/` 生成可供 Cyrene 导入的 ZIP。

隔离宿主测试只使用合成消息、内存模型、内存 Secrets 和空会话服务；不会启动 Electron、读取
真实模型配置、调用网络模型或访问现有用户数据。测试目录在结束时校验边界后删除。

额外的 `npm.cmd run electron-host-smoke` 会在 `-N/local-plugins/.test-runtime/electron-host/` 中
启动一次独立 Electron 插件运行时，用合成 `app-settings.json` 显式启用两个插件并禁止模型调用；
不启动正式 Cyrene，也不验证最新上游提交的完整原生 Chat 回合。

完整主程序的隔离测试只能走 `scripts/run-full-electron-host-smoke.mjs`，不能使用仓库根的
`npm start`、`npm run dev` 或 `start.bat`。运行器先只读哈希正式 Cyrene 的已知用户数据根，
任一目录不可完整读取即拒绝启动；然后在 `-N/local-plugins/.test-runtime/` 下为每次运行创建
独立目录，退出后只清理本次运行目录，并仅对子进程重定向 AppData、主目录、临时目录和 Electron 路径。
合成启动拦截登录项、热键、子进程和主进程常见网络入口；退出后复核保护根目录。
完整宿主测试还要求合成设置中的桌面 Chat 原生记忆已关闭、两项插件均实际启用；不代表已完成真实聊天回合验收。
在新上游工作树执行前，必须先在该工作树构建主进程、preload 和渲染端；少编译 preload 会让原生页面缺少
`window.chatStore`，不能把这种测试入口故障误判为插件故障。测试运行目录始终在当前工作树的
`local-plugins/.test-runtime/` 内；嵌套 `.upstream-latest` 布局也会把正式保护根锚定到同级的原版 `Cyrene-Agent`。
可先执行 `node scripts/run-full-electron-host-smoke.mjs --preflight`，此命令不启动 Electron。
哈希是事后检测，不是操作系统级写入禁止；若正式 Cyrene 仍运行、文件被占用或任何保护根变化，
不得把本测试视为已证明“全部用户数据零影响”。

需对当前正式数据做一次性只读结构预检时，可在确认正式 Cyrene 已退出后运行
`node scripts/run-full-electron-host-smoke.mjs --real-snapshot`。入口先在本次隔离运行目录中复制
Roaming 用户数据并逐文件核对内容；原生 `userData` 仍是单独的合成空目录，不会加载原记忆或迁移
其 schema。插件窗口只预检快照中的 `memory.json`，不导入、不更新激活值、不请求模型；退出时
删除本次快照和运行目录。该测试**不是**真实会话、真实模型或完整记忆迁移验收。若进程被强制终止、
系统断电或清理失败，必须先人工核查并清理本次 `run-*` 目录，不能宣称临时数据已删除。

需要查看完整主程序和插件界面时，使用同一入口加 `--visible --real-snapshot`；插件窗口会显示
这份快照的只读结构统计，主程序仍使用隔离的合成空库，网络和子进程仍被阻断。关闭窗口或达到
十分钟测试上限后，外层入口复核正式数据并删除本次运行目录。单独 `--visible` 也只用合成数据，
退出时清除本次运行目录。不要用仓库根的启动脚本替代隔离入口。

构建不会自动安装或启用插件。只有用户在 Cyrene 插件面板中选择 ZIP 并明确启用后，插件
才会进入主进程运行。

## 提交到官方插件仓库

`artifacts/<plugin-id>/` 是符合 `Cyrene-Plugins/plugins/<plugin-id>/` 要求的可审查产物，
只包含 Manifest、编译后的入口、插件说明和必要资源。提交时：

1. 只复制 `artifacts/<plugin-id>/`，不要提交本目录的源码、测试、依赖或构建脚本；
2. 按官方要求更新 `registry.json` 和仓库根 README；
3. 一个 PR 只提交一个插件；
4. 不上传 `artifacts/<plugin-id>.zip`，ZIP 由维护者在合并后统一生成；
5. PR 中逐项说明网络访问、文件读写、子进程、宿主能力与数据存储行为。

## 新增插件

复制 `plugins/plugin-template/`，并同时修改：

- 目录名和 `manifest.json` 的 `id`；
- 工具 ID，必须以 `<plugin-id>_` 开头；
- 名称、版本、描述、作者和依赖声明；
- 插件 README 中的功能、配置、数据行为、风险与限制；
- 对应的契约测试。

有后台任务、窗口、定时器、网络连接或子进程时，必须响应 `ctx.signal`，并通过
`ctx.onDispose()` 或幂等的 `unregister()` 完成清理。
