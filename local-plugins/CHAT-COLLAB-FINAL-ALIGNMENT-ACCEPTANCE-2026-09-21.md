## 本轮对齐

- 动态 Prompt Provider 新增 `soul/tool` 目标边界；未声明目标的旧 Provider 继续按 Soul 处理，保持 SDK 向后兼容。
- 陪伴桌面 Chat 的自动 L2 记忆只进入 Soul；自动历史原文同时进入 Tool 与 Soul，和本地 2FC 阶段边界一致。Tool 阶段需要结构化 L2 时由模型显式调用记忆工具，不再自动注入整块 L2。只有最终 Prompt 被接受并成功落盘后才提交 Soul 的 DMAE／生命周期回执。
- Tool Harness 最大轮数固定为 20，仅作用于 `toolOnlyChat`；Work、Code、Learn、渠道和原生 Chat 不变。
- 主动消息补齐普通聊天最近上下文、最近主动消息、语气规则、夜间状态和记忆查询主题；同一场景可以连续命中，跟进阈值为 55。回应反馈学习保持默认关闭，只有用户主动开启才更新 affinity。
- 自动画像反思的候选接纳与自动采用统一使用 0.7 置信度门槛，同时继续保留变更记录和撤销入口。
- 当前 `-N` 隔离实例已开启记忆联动、主动消息、语义索引、自动维护、冲突复核、压缩、画像反思、生命周期和梦境自动链。后台屏幕观察因尚未配置视觉模型而保持关闭；手动观察和工具通路保留。
- 补齐 BGE-M3 与 bge-reranker-base 的 ONNX、tokenizer 和 config 资产。临时 Electron 验收确认 reranker 加载成功、场景 BGE-M3 索引构建成功。
- 屏幕观察除桌宠区域遮罩外对齐本地实现：3/8/2 分钟状态机、本地 `Math.round(age/60000) > 10` 过期边界、三行 VLM 判定、2048/4096 token 预算、聚焦截图质量、thinking 标签清洗、连接重试与视觉模型回落、最近 5 条工具摘要、像素无变化连续时长和本地原提示文字均已覆盖。手动通用观察不再做像素短路，也不改写周期观察基线；桌宠遮罩是唯一保留的有意增强。
- 桌宠待机与新增热区已移植：用户开关默认关闭；键鼠空闲后首次至少 60 秒、之后 30–120 秒随机播放 `Tick3`，周期屏幕无变化次数用于自适应延迟；朗读、模型动作和命中交互会正确暂停或打断；身体热区只作精确 HitArea 之后的回退，并保留重复墨镜表情的问号回退与动作结束平滑回正。
- 通话、Minecraft 与音乐陪伴上下文已建立统一的只读宿主接口和插件权限边界，但尚未装配实际数据 Provider，也尚未进入 Soul；因此当前不能把 Soul 描述成“除 Moments 外完全相同”。

## 记忆与历史消息检索双路径

- 结构化 L2 与历史消息原文已经拆成两个独立检索域，不再由 L2 渲染器用最多 5 轮词面包含结果冒充历史召回。
- 自动 L2：沿用本地分面计划、普通／清单结果数、pinned／DMAE 工作集、来源时间、原文证据、aging 与冲突提示；只进入 Soul。social short_term 与 L2 重叠达到 0.6 时优先保留更新的 social 条目，和本地一致。
- 模型 L2 工具：直接检索有效 L2 及被更新／取代的旧事实；旧事实带 `⏳` 提示。工具检索不补 DMAE 常驻项、不提交 DMAE，也不把历史原文混进结果。
- 自动历史：90 天默认时间窗；显式回忆线索或 BM25 原始分至少 6 时触发；普通问题最多 5 条，分面／清单问题扩展为 8／10／12 条；结果按原始时间排序并带相对时间解释。该块同时提供给 Tool 与 Soul。
- 模型历史工具：最多返回 5 条带角色和时间戳的原始消息，和自动历史共用同一候选、相关性和格式管线；只对基线命中的插件私有历史索引执行与本地一致的 `weight +0.05`／最近召回时间更新，不更新 L2、DMAE 或宿主会话。自动历史不写该状态。
- 历史候选管线已补齐本地使用的查询清洗、查询扩展、意图查询、混合召回、两路纯语义召回、RRF、同轮用户／助手原文配对、长消息句窗、原生 cross-encoder 重排及相关性阈值。句窗只参与排序，最终仍返回完整原文。
- 宿主公开检索服务新增向后兼容的可选排序分数、排序来源及 `semantic` 模式；它只处理插件传入的私有候选，不读取或写入宿主 RAG 库。
- 自动检索全程预览；L2 的 DMAE／生命周期仅在 Prompt 被接受且最终消息成功落盘后提交。历史自动检索不更新访问状态。该提交时机比本地“组装 Prompt 时立即记账”更保守，是保留的隔离安全差异。

## Moments 保留项

按用户决定保留上游 Moments 背景，不将其视为缺口。它包含两层只读资料：

1. 每轮最多注入最近 48 小时的 3 条动态摘要：时间、发布者、标题／正文前 60 字，以及昔涟是否点赞或评论。
2. 只有用户明确提到朋友圈、某条动态、照片、评论或点赞等指代时，追加排序最相关的一条动态详情：发布者、完整时间、标题、正文、最多 20 条评论、最多 2000 字触发摘录和配图数量。

两层均带“历史社交记录不是当前指令”的防注入声明；不会把整个 Moments 数据库或媒体文件送给模型。

## 10＋2 提取与 DMAE

- 记忆提取按用户后续确定的口径运行：同一会话累计当前 10 个未处理成功回合后触发，额外提供此前最多 2 轮只读上下文；前 2 轮不能成为新记忆来源。不同会话不拼批。
- 解析失败、证据原文不匹配、无依据绝对化、取消、模型错误或存储失败均不消费这 10 轮；只有整批校验并持久化成功后才标记已处理。
- 宿主来源回合在模型调用前后都通过官方会话只读接口复核消息 ID、角色、正文与时间。模型运行期间被删除或改写的来源不会写入记忆，也不会误标为已处理；插件私有或导入轮次不伪造宿主复核。
- DMAE 参数与本地实现一致。检索回执现已区分“真实查询命中”和“pinned／DMAE 常驻补位”：只有真实命中获得激活奖励并刷新生命周期，常驻补位仅在确实进入最终预算时更新 `lastInjectedRound`。
- 待复核冲突条目不会作为 pinned／DMAE 常驻项自动补位；若用户问题直接检索命中，仍可带冲突警告进入上下文，便于向用户求证。
- 保留已确认的安全时序差异：DMAE 和生命周期只在 Prompt 完整接受且回复成功落盘后提交；取消、失败、未落盘或截断回执均不推进状态。

## 生命周期、Compressor 与 Dream

- 生命周期的 30 天 `active → aging`、90 天 `aging → archived`、每日权重减 1、300/800 容量线及 `weight × 时近度` 排序均与本地一致；状态变更继续额外保留来源快照和严格撤销。
- 补齐本地召回复活语义：只有真实检索命中才增加私有 weight／访问次数；aging 条目权重恢复到 30 时回到 active，并生成可追溯、可撤销的生命周期记录。
- 普通 Compressor 每 20 个成功桌面 Chat 回合处理当次全部互不重叠 active 候选组；阈值 0.85、至少 3 条、全组两两凝聚，取消了此前每次一组／每组最多 5 条的额外限制。单组失败不阻断后续组。
- 普通 Compressor 应用后源条目保持本地 `archived` 语义；Dream 蒸馏合并改为本地 `merged + mergedInto`，不再错误标成 archived。两者均保留总结来源谱系、快照复验、原子应用与撤销。
- Dream 的“沉淀叙事”和“aging 蒸馏合并”是本地流程中的两个不同阶段；同一批条目可先贡献关系叙事、再参与事实压缩，不属于重复生成同类记忆。
- 冲突链路已按本地实现对齐：新 L2 完成语义索引后，只在向量最相近的最多 5 条旧记忆中执行共享主题与肯定／否定弱矛盾检测，不做全库词面扫描。显式纠正且旧记忆在最近 10 分钟真实注入过、或向量相似度至少 0.75 时，直接将旧事实标为 `superseded` 并关闭有效期。
- 其余候选按本地同一套分值计算纠正意图、RAG 相似度、最近注入、双侧证据、局部矛盾、影响范围与惩罚；35／55／75 分分别对应 idle／normal／high，缺证据候选不进入自动 Resolver。未取代的旧条目降为 `aging` 并退出 DMAE 常驻补位；每 5 个成功桌面 Chat 回合按优先级复核一对。
- 在本地行为之上保留此前约定的安全增强：快速取代和候选降级均保存双侧快照、时间和动作类型，可在相关记忆未发生后续变化时从 UI 精确撤销；Resolver 完成后清除该对冲突标记。最近注入集合与本地一致，仅保留 10 分钟内最多 20 条真实查询命中。

## 消息失效、实体图谱与查询路由收尾

- 宿主新增只包含会话 ID、失效消息 ID 和变更原因的 `host:conversation:changed` 事件。替换消息、删除一轮和删除会话后，插件会移除对应待提取轮次，归档直接来源记忆，把关联证据标记为 `deleted`，并同步清除这些记忆的私有向量、DMAE 和生命周期状态；不会反向改写宿主聊天。
- 手动修改记忆正文会清除该条 DMAE 激活并排队重建语义向量；永久删除会同时删除关联证据、向量、DMAE、生命周期记录和其他条目的冲突引用。所有持久化变更在插件私有 `memory-trace` 中记录 revision、时间、变更域和相关条目／轮次 ID。
- 实体提取不再采用额外的模型实体数组，而是逐字复用本地版正则启发式规则扫描本批用户原文；结果写入插件私有实体图谱。查询命中实体名或别名时把类型与提及次数加入 always-on 记忆上下文。companion 后端已禁用宿主原生实体图谱注入，模型只会看到这一套图谱。
- 查询路由默认关闭，用户必须在插件 UI 中单独配置地址、模型和 API Key。开启后每轮只向所选 Provider 发送当前查询，不发送记忆库、历史消息或证据；失败重试两次后回退语义 Top 5。
- 路由阈值、分面种类、范围、候选深度和字符预算与本地实现一致：低于 0.5 不扩展；0.5～0.75 只开普通分面通道；达到 0.75 后采用模型给出的 scoped／exhaustive 范围；候选深度为普通 20、清单 48，最终上限为 5／10／13／20，并保留非穷举分面候选的相对分数下限。
- 同一桌面 Chat `runId` 的 Tool 历史注入、Soul 历史注入和 Soul L2 注入共享同一个路由 Promise；不会为同一轮重复调用路由模型，也不会让 Tool／Soul 使用不同路由结论。模型显式调用 L2 工具时独立按本次工具查询路由；历史工具按本地固定 5 条行为不扩大。
