# 昔涟地下城决策预演 v0.1.1

这是初代《Minecraft Dungeons》的独立决策阶段。仅生成「昔涟这一步应做什么」的语义提案，不创建手柄、不发输入、不启动游戏、不读取游戏内存或存档，不调用模型或现有 Chat 服务。`dungeons-input` v0.1.0 和其 ZIP 保持原状，可同时继续人工输入验收。

## 使用

导入 `dungeons-decision.zip`，启用后重新打开设置，在「工具配置」底部进入「昔涟地下城决策预演」。选示例并点「重新加载示例并预演」，查看动作和原因；反馈模拟完成/失败，或停止、重置。预演记录只存于插件内存，停用插件后丢弃。

包含 12 个示例：待命、跟随、路径不明、近战、远程、治疗、撤退、闪避、救援、倒地、低可信度和菜单。手工 JSON 走同一校验和决策路径。`source` 仅允许 `simulation` / `manual`，面板没有真正的截图识别；`foreground` 也是输入中的声明，不是操作系统前台检查。

## 决策约束

- 观察时间超过 1500ms、来自未来、画面失焦、菜单/加载、自身倒地或关键状态未知时选择释放。可信度阈值 0.85 是本版策略参数，未做游戏数据校准。
- 优先处理迫近危险，然后低血量治疗/撤退、安全救援、归队、短时协助战斗和跟随。低血量阈值 30%、救援自身血量要求 60% 均为预演策略。
- 跟随、撤退和闪避需要明确路径或安全落点；不猜路线、不追逐远敌、不操作复活或角色菜单。近战范围、射线、药水、闪避和救援提示须由观察明确给出；箭数未知或为零不射击。
- 位置是画面中 0..1 坐标。0.12 跟随距离、0.28 归队距离和 0.1 救援距离仅为屏幕距离启发式，不代表世界距离、近战范围或可行路径。坐标未转换为手柄摇杆。
- 每次仅提议 200ms 动作（救援 400ms），随后必须新观察；不把短时救援提案当作救援完成。一个待反馈提案，重复或乱序观察不重放；行动条件改变先取消旧提案并释放。模拟使用药水/闪避后，须先观察不可用再恢复可用，不臆造游戏冷却秒数。
- 反馈只接受 `simulated-complete` / `simulated-failed`。所有记录始终携带 `simulationOnly=true`、`gameInputSent=false`、`gameOutcomeVerified=false`。语义主体固定为昔涟，绑定用户的位置仅用于队友目标，不选择 P1 输入。

## 接入实机前还缺什么

1. 输入验收确认 P1 键鼠、P2 虚拟手柄、角色归属和按键映射。
2. 建立绑定 P2 的实时画面观察：角色位置、血量/倒地、药水/闪避就绪、队友、威胁与可走路径。不能把模拟 JSON 直接作为实机观察。
3. 标定画面方向到摇杆方向和实际按键，再接入执行器。每次执行重新核对真实前台、观察期限和已确认 P2 句柄，结束后释放；游戏效果由后续真实画面验证，不接受模拟反馈冒充结果。

当前规则可以在未来接模型前作为短动作选择与停止保护。此版没有 LLM 决策、视觉模型、导航地图、自动战斗或真实游戏执行循环。先验证这些可检查的策略，再接可信观察与设备执行。

v0.1.1 的面板等待宿主初始化完成后才加载场景，避免 iframe 登记前的第一条请求被忽略；策略和执行范围未改变。

## 验证

`npm.cmd test -- --run tests/dungeons-decision.test.ts` 验证策略优先级、未知/异常输入、重复/乱序、取消、反馈、能力就绪与面板。`node scripts/build-dungeons-decision.mjs` 只构建此插件。原 MC bot 的观察/决策/结果核对结构用于设计参考，没有导入旧 bot 或复用其键鼠执行器。

本版已通过 54 项 Vitest 策略/会话/面板测试、定向 TypeScript 检查和 8 项隔离 Electron 原生检查（真实 ZIP 安装器、12 个打包场景、官方面板桥、模拟反馈、停止及停用）。输入插件 ZIP 的 SHA256 在本轮前后均为 `3032225073ffa992fa235254d04416728213a58a0cb0d7a770e88aebef91df76`，没有重新构建输入插件或运行设备测试。这些结果不代表实机视觉识别、输入兼容或自动陪玩已完成。
