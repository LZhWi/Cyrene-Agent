# 独立陪伴聊天 0.13.0

0.13.0 通过插件自有只读 IPC 向上游原生 Chat 提供与模型 life-context 同源的“正在××／休息中”短状态；
宿主只显示，不读取插件私有设置或复制日程算法。插件停用、日程关闭、原生后端及其他模式均不显示。

0.12.0 为动态上下文声明稳定顺序：生活日程在记忆前，WorldBook 在记忆后，避免插件扫描或启用顺序
改变最终 Soul 的近端权重。旧宿主若不支持 `priority` 仍可加载插件，但只能退回注册顺序。

与 companion-memory 一起使用。聊天窗口、会话存储、提示词组装和模型调用独立于宿主原生聊天。
0.2.0 移除开发机绝对路径绑定；运行状态只写入宿主分配给本插件的私有存储目录。

## 模型来源

- 默认复用当前主程序：调用官方 `deps.llm.generateText`，使用加载插件的宿主配置，不读取另一程序。
- 只读配置文件：仅在用户主动选择并保存后读取所填 `model-settings.json`；文件不复制、不修改，
  凭据只在主进程内存中使用且不回显。当前支持已确认的顶层 OpenAI 兼容配置（含 Kimi）。
- 自己配置：提供 HTTPS API Base URL、模型、API Key。点击保存后密钥进入官方私有 secrets 服务，
  普通配置只保存来源、地址、模型和提示词。允许本机 HTTP；拒绝 URL 内凭据及重定向。
- 此处选择只作用于独立聊天。companion-memory 的提取、重排和人工复核直接使用当前宿主官方模型服务；
  本版聊天为非流式文本，无工具执行、图片、TTS 或 Live2D 联动。

默认稳定人格完整组合本地版 `system.md`、`identity.md`、`soul.md`、`canon_quotes.md` 与所选
风格。本地 Tool→Soul 协议保持不变，只对失效的旧 Playwright 插件说明做确定性兼容转换；工具目录、
权限和调用过程仍由上游 Harness 管理。`tools_system.md` 通过独立稳定 Tool 层注入，最终回复由无 tools
的 Soul 请求生成。本地 `tone-rules.md` 继续复用宿主的场景匹配算法，`tone-anchor.md` 只在最终 Soul
生成点作为近端锚点追加；二者不会进入 Tool 阶段。界面可选本地五套风格，并可在末尾追加自定义指令。
只有点击发送才发聊天请求；点击并确认“提取待处理记忆”才发额外提取请求。提取使用记忆插件统一的
“当前 10 轮可写＋前 2 轮上下文”批次；不足 10 轮时保留待处理队列。

## 你的生活

- 默认启用与本地版相同的确定性拟态日程：本地时间凌晨 4 点换日，上午、下午、晚上各 1–2 项，
  同一天跨链路结果一致，23:00–07:00 不声称正在执行某项日程。
- 插件运行且日程启用时每 15 分钟推进一次生活时钟；已结束时段写入插件私有的角色世界生活记录。
  应用关闭或休眠后会在下次启动补算；日程被主动关闭期间不补算。间隔超过 72 小时只写一条概括，不逐项补满。
  记录没有按天数自动清理；聊天默认只注入当天记录，询问昨天、前天或具体日期时按日期读取历史记录。
- 日程由动态 Prompt Provider 注入，只在宿主明确选择 `companion` 的桌面 Chat 生效；原生后端、
  Work、Code、Learn 和渠道不会收到。稳定人格前缀不含日程，避免破坏提示缓存。
- 独立聊天和插件主动消息复用同一份日程。纪念日保存在插件私有设置中，每行使用
  `MM-DD 标题` 或 `YYYY-MM-DD 标题`；不会读取或改写宿主的 `important-dates.json`。
- 使用规则限制模型只在用户问起、话题强相关或主动消息时自然引用，禁止把拟态日程说成现实经历。

## 世界书

- 内容使用本地版五份 WorldBook，并保存在插件包内；不会读取或改写宿主的世界书目录。
- 激活采用上游 V5.1 算法，包括饱和衰减、最近六轮重复命中抑制、用户/模型静默计数、级联和
  archived 冷唤醒。这是在逐项比较内容与算法后确认的组合，不代表本地旧 V4 算法的逐字复刻。
- 只在宿主明确选择 `companion` 的桌面 Chat 中预览和注入；原生后端、Work、Code、Learn、
  朋友圈、外部渠道与插件无头任务保持上游原生行为。
- 激活状态只写入本插件私有 `worldbook-state.json`。生成、失败和取消阶段均不写入；只有宿主确认
  本 Provider 内容完整进入最终插件上下文、且最终助手消息已经落盘后，才按对应 runId 原子提交本轮状态。
  若旧宿主不支持消费回执，WorldBook 仍会注入，但激活状态保守地不推进。

## 主动消息

- 默认关闭；只有用户在设置中明确启用后才注册周期检查。
- 至少连续静默 20 分钟才生成；首条真实发送采用 2 小时全局冷却，未回复时第二条至少间隔 3 小时，最多连续 2 条未回复。
- 模型必须返回 `send` 或 `silent` 的结构化决策；silent 和无效输出都不投递、不增加未回复计数，并进入 10 分钟冷却。
- 自动判断先按本地版公式累积 Desire，再从 morning、topic_followup、evening_checkin、late_night、idle_daze、work_break、back_from_away 七个场景评分选出候选；候选只是选题线索，模型仍可 silent。
- 回应反馈学习默认关闭且必须由用户主动开启。开启后，用户回复主动会话会提高对应场景 affinity；不会按固定时限判负，只有系统下一次已有合格场景、准备主动开口时，才把上一条仍未回复的消息结算为忽略。关闭时不修改 affinity、Desire 或其速率。第二条未回复消息允许沿用同一场景，但评分至少 55。与上一条仅标点或空白不同的重复文本会被抑制。
- 反馈学习开启后，插件投递会显式请求宿主在最后一条主动消息下显示一次性“忽略”按钮。点击只结算该消息对应的场景负反馈并保留消息，不清零未回复计数；普通 Chat、手动主动消息测试、反馈关闭状态和其他插件消息均不显示。宿主事件只含插件、会话、消息 ID 和动作，不含正文。
- 每 5 分钟检查一次，只在策略允许时调用模型。锁屏时始终不发送；23:00–08:00 仅当最近五分钟内仍有键鼠活动时允许判断，避免把仍在使用电脑的夜间用户一律误判为离开。
- 原生桌面 Chat 的 `host:turn:started` 或独立聊天用户发送会立刻增加 generation epoch、清零未回复计数并取消迟到生成。
- 生成后会再次核对 epoch 与策略，确认仍有效才调用受限 `assistant-delivery`；只有宿主确认落盘后才记录冷却。
- “发送主动消息测试”仍需点击和二次确认；它绕过时间门槛，但真实投递会计入冷却和未回复次数。
- 桌面 Chat 选择陪伴后端且主动消息投递目标为本地时，宿主自动旁路原生主动聊天，避免重复发送；微信、飞书等渠道仍保持上游原生实现。
- 天气场景通过 `weather-context` 宿主能力读取结构化、只读且带 30 分钟有效期的快照。插件只能看到天气类别、温度、降水和可用的今昨最高温，不会获得城市、坐标、Key 或宿主配置；查询失败五分钟后才重试。雨天、显著降温与舒适晴天按本地评分公式参与候选，并共享每日一次天气场景限制。

协议参考：[Kimi 对话补全](https://platform.kimi.com/docs/api/chat)。本版直连不设置固定 temperature，
只发送模型、消息、输出上限与非流式标志，推理模式采用服务端默认。文件引用复用地址、模型和密钥，
尚未迁移原程序所有采样/推理设置；需要完整宿主请求适配时选择“当前主程序”。

## 数据与风险

- 写入：仅宿主分配的插件私有目录内 `chat-state.json`、`model-config.json`、
  `worldbook-state.json`，自定义凭据由 secrets 管理。
- 读取：用户明确选择的原模型配置；不自动读取宿主对话/记忆，不加载宿主私有模块。
- 网络：所选模型地址，发送系统提示词、本插件最近 24 条消息、检索资料和本次输入。
  使用当前宿主服务时网络目标由宿主设置决定。不会执行模型返回的代码/HTML。
- 插件间事件传输本插件聊天/提取数据，不传密钥；事件不是安全隔离通道，同宿主插件必须可信。
- 记忆联动默认关闭；关闭时可单独聊天且不等待记忆插件，启用后两个插件必须同时运行。
- 原生桌面 Chat 可在 Tool 阶段按需调用只读记忆查询；查询不更新激活值或访问统计。
- 原生桌面 Chat 可按需观察当前主屏；宿主仅返回视觉摘要，原始截图不写盘、不交给插件，通用摘要
  30 秒内复用。后台观察默认关闭，显式启用后按 3 分钟观察、低变化 8 分钟、失败 2 分钟重试；
  宿主先排除自身可见桌宠窗口区域，再用 64 像素宽的内存位图判断其他画面是否基本不变；未变化时复用摘要且不调用视觉模型。
- 停用会取消模型调用、关闭窗口、拒绝未完成 RPC。消息成功提交后才交付记忆；失败交付保留 outbox。
- 状态文件访问会校验真实存储根与直属文件路径，拒绝通过链接逃逸；宿主自身的数据目录生命周期不由插件控制。
