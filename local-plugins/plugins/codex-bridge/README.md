# Codex 任务工作台（测试版）

独立窗口插件，不改 Cyrene 主聊天发送链路。用户消息以原始文本提交给本机 Codex App Server，所选技能作为结构化 skill 输入传递。Cyrene 宿主模型只在最终回执解读时调用。

## 使用

1. 在 Codex 中使用 ChatGPT 账号登录。本插件只接受 ChatGPT 认证，不回退到 API Key；额度以账号和模型实际限制为准。
2. 在 Cyrene 插件页导入 `codex-bridge.zip`，启用并打开“Codex 任务工作台”。
3. 填写工作区绝对路径，点击连接。Windows 默认发现本机 Codex 安装目录，也可指定可执行文件绝对路径。
4. 选择模型、支持的思考强度、可选技能和执行范围。只读为默认；工作区写入允许 Codex 在指定目录处理文件。请求提升权限时显示审批卡，须用户回答。
5. 输入任务并发送。可查看原始回执和文件 diff、取消执行、回答 Codex 的问题，或选择已结束任务继续同一会话。
6. “完成后由 Cyrene 解读回执”使用宿主当前配置的模型，按宿主的模型配置计费；不自动继承完整陪伴人格和私有记忆。关闭后只显示 Codex 原始回执，也可以手动解读。

窗口关闭时任务仍由插件管理；停用插件或退出宿主会断开自有 App Server，未结束任务标记为状态待核对。再次连接后点击“核对回执”；不能确认结束时不会自动重新提交，也不声称外部副作用已停止。

## 当前范围

- 单个任务同时执行；每次消息保存配置快照和 threadId / turnId。支持新任务与已结束会话的后续轮次。
- 模型和技能目录来自当前执行环境，不保证桌面宿主专有技能在独立 App Server 中可调用。
- 消息原文不加前缀、不经模型改写；技能采用 App Server 的显式 skill 输入。
- 支持命令/文件变更审批和 `item/tool/requestUserInput` 提问。只提供单次批准，不扩展会话级权限。
- 首版未实现 MCP 自定义表单、URL 授权流和额外权限授予，遇到这些请求会明确拒绝并显示原因；不能承诺所有技能可用。
- 不提供附件上传、普通聊天历史注入或自动登录。图片/文档处理可在消息中引用工作区文件路径。
- 测试版的模型、思考强度、技能、工作区和执行范围是明确支持的配置，不开放全部底层实验参数。
- 本机 Codex 历史仍保存在 Codex 自己的数据目录；插件配置与回执保存在宿主分配的插件私有存储，不读取或复制认证令牌。

## 开发验证

### 原生 Code 接入（第一阶段）

更新宿主后，Code 工作区输入区域提供“Cyrene（原生） / Codex”选择；默认原生。安装并启用本插件后，选择 Codex，绑定工作目录并点击“连接 / 刷新目录”，再选择模型、思考强度、技能和执行范围。只发送该输入框的文本，不自动传入原生历史或附件。两种执行器的草稿和配置独立，Codex 出错不会自动改走原生模型。

Code 的任务卡显示进度、提问、审批、原始回执、文件变化及可选宿主模型解读。默认恢复当前 Code 会话的上一条 Codex 会话，也可显式新建；按 Code 会话和工作目录隔离记录，重启后未知任务需先连接并核对。执行器运行中禁止从界面切换线路。记录暂存于插件自己的存储，不混入 Chat 的消息或记忆。

本阶段只接入 Code。主进程拒绝 Chat / Work / Learn 会话及非工作区窗口调用；这些模式的原生发送入口保持不变。需要同时更新宿主和插件包；只升级 ZIP 不会给旧宿主增加原生入口。

`node scripts/test-code-executor-electron.mjs` 验证原生 React 组件 → preload → 主进程校验 → 插件的完整隔离链路，包括原生发送、Codex 提问、回执解读、释放和切回原生。该测试模拟 Codex 协议和宿主模型，不代表完整日常应用实测。

在 `local-plugins` 目录运行：

```powershell
npm.cmd exec -- vitest run --config vitest.config.mjs tests/codex-bridge.test.ts
node scripts/build-codex-bridge.mjs
node scripts/test-codex-bridge-electron.mjs
node scripts/test-codex-bridge-ui.mjs
```

构建只更新该插件产物。Electron 测试使用独立 userData 和协议模拟器，不读取正式 Cyrene 数据、不调用真实模型。真实 Codex smoke 脚本需要显式 `--live`，默认只发一条只读任务，关闭 Cyrene 模型解读；增加 `--release-test` 会再续接一轮，并验证独立客户端可以接管已释放的会话。

任务完成、失败或确认中断后，先保存回执，再结束插件专属 App Server 并等待进程退出，界面显示“会话已释放”。下一次提交自动重新连接，继续任务仍恢复原 threadId，不删除或归档历史。状态未知的任务仍需先核对，不会自动重发。Cyrene 解读不需要持有 Codex 会话。

## 本次验证（2026-10-02）

- 插件及测试定向 TypeScript 检查通过；全量 local-plugins 类型检查仍有两组旧实验测试引用外部 Cyrene-Agent 路径失败。
- 核心测试覆盖原文与技能传递、重复提交、认证限制、过期提问、审批拒绝、断线核对、继续会话、取消确认、回执解读去重和停止阶段禁止写入。
- 隔离 Electron 使用真实插件包、preload 与 IPC，协议和宿主解读模型使用模拟实现；提问输入保留、回答、拒绝审批、回执和停用清理通过。它不是完整 Cyrene 主程序验收。
- Electron 的隐藏截图存在 UnknownVizError；另用本机 Edge 检查 1080px 和 760px 界面截图及水平溢出，均通过。
- 真实 Codex 0.159.0-alpha.12.1：ChatGPT 订阅认证、8 个模型、68 个已有技能发现成功；普通任务返回 CYRENE_PLUGIN_OK；额外发现隔离目录的测试技能并显式传递，返回 CYRENE_SKILL_OK。
- 没有对真实 Cyrene 主模型执行付费解读，也没有逐个验证已有技能、真实写文件审批或所有插件依赖。本包未安装进日常 Cyrene 数据目录。
