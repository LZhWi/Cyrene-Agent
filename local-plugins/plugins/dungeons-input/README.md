# 昔涟地下城输入与营地跟随测试 v0.2.0

Windows Xbox PC 版《Minecraft Dungeons》初代：P1 保留原生键鼠，第一只虚拟手柄保持空闲，第二只用于 P2。用户已反馈本地双人输入测试通过，并提供两名角色进入营地的截图。v0.2.0 新增独立的角色观察、移动校准和营地短距离跟随；新增跟随尚需游戏内人工验收。

## v0.2.0 营地跟随验收

更新插件会断开旧插件创建的手柄。先在游戏营地结束本次测试，再断开两只测试手柄、停用旧插件、导入新版并启用；重新创建手柄，用第二只加入 P2。不安装或更新驱动，不启动/关闭游戏。

1. 两名角色站在营地同一块平坦空地，保持中等距离，附近不要有障碍、悬崖或交互菜单。确认第二只手柄只控制 P2。
2. 点新增的「倒计时后只观察」，在上方的倒计时内切回初代。此步骤不移动；完成后回面板，检查预览的橙色 P1、青色 P2 框是否准确对应角色头上的标记。预览是这次观察的静态画面，不是直播。
3. 预览正确才勾选营地确认，点「校准并跟随一轮」，在倒计时结束前切回游戏。校准时保持 P1 静止，P2 会向右、向上各短移 150ms。通过新画面的 P2-P1 相对位移计算两个摇杆轴的方向，消除共享镜头平移；校准不足、位移异常或方向不独立就停止。
4. 随后最多六次 150ms 移动接近 P1，每次归零后等 250ms 再读取新画面。测试第一轮时保持 P1 静止、观察是否只有 P2 在接近。到达附近、间距异常、窗口改变、标记丢失/重复、连续两次没有接近、明显反向、失焦、F12 或开始后的 12 秒期限都会结束本轮，不自动恢复，不保存旧校准。
5. 在下一轮测试中，用 F12 或切出游戏结束动作；回到面板应显示停止原因，切回游戏不得继续。面板的「停止观察／跟随」同样结束整轮，手柄保持连接，重新开始需要再次点击。此版不能完整识别菜单，本轮不要打开菜单或进入关卡，需要这些操作时先 F12 停止。

识别只使用彩色 P1/P2 像素字形，不读取角色内存、不调用模型或现有 Chat 截图流程。仅截取精确白名单中的初代前台客户区；用户明确请求的预览在本机内存中保留一张 PNG，后续跟随仅返回位置与状态，不上传或保存画面。GDI 可见画面若黑屏、被遮挡、标记过小、色彩改变或匹配失败，停止并报告；目前仅用用户提供的 2560×1600 营地截图及其 1280×800 缩放确认识别，不能据此保证其他分辨率/HDR。

这是一轮短距离、人工确认空地的跟随测试，不能理解地形、绕障、识别生命值/危险或战斗；角色标记识别不等于完整场景/菜单识别。先前 `dungeons-decision` 的治疗/战斗/救援规则继续独立模拟，未把未知生命值、危险状态伪装成已观察结果，也未接入真实攻击按钮。实时跟随规则在拥有两只手柄的输入进程内执行，避免第二个插件重复创建设备或并发控制；既有 Chat、主程序截图和模型设置未改动。

`DungeonsInput.exe --capture-status` 只读检查新截图后端，返回前台客户区的标记或拒绝原因，不创建手柄，不输出/保存 PNG，也不发送输入。本机只读检查已确认非游戏前台拒绝和截图进程 DPI 设置成功；实际游戏客户区捕获与跟随反馈仍待面板验收。

v0.2.0 验证：37 项输入/面板 Vitest 加既有 54 项独立决策测试通过，定向 TypeScript 检查通过；编译后原生检查为 25 项旧输入保护与 27 项新识别/跟随检查。使用用户提供的营地/角色选择截图，15 项只读截图夹具检查确认原图、1280×800 缩放的角色坐标正确，重复 P2 与菜单拒绝，并记录其他缩放识别失败。11 项实际设置页 Electron 检查覆盖官方桥、初始化时序、默认禁用、驱动探测及提供截图的真实画布标记预览；未创建额外设备、捕获实际游戏画面或发送游戏输入。这些检查不等于真实游戏跟随通过。

## 范围与依赖

- 仅允许本机核验的初代游戏进程：`C:\XboxGames\Minecraft Dungeons\Content\Dungeons\Binaries\Win64\Dungeons.exe`，以及已注册应用包的精确别名 `C:\Program Files\WindowsApps\Microsoft.Lovika_1.17.0.0_x64__8wekyb3d8bbwe\Dungeons\Binaries\Win64\Dungeons.exe`。v0.1.3 已只读核对运行中的进程路径及 `Get-AppxPackage Microsoft.Lovika` 注册信息。根目录启动器、其他同名进程、二代和未核验的应用包版本均不接受输入。
- 二代 `D:\Minecraft\Minecraft Dungeons II` 仅检查了安装配置；此版不控制二代。
- Windows x64 / .NET Framework；用户需安装 ViGEmBus。测试工具不安装驱动，不启动或关闭游戏，不改游戏文件、存档、按键设置，不读取聊天或调用模型。
- ViGEmBus 已停更。准备的是官方最终版 1.22.0（移除了旧更新器），驱动安装包不放进插件 ZIP，不自动运行。
- 随包 ViGEmClient.dll 来自官方 PyPI 的 vgamepad 0.1.0 源码包，仅使用其中 x64 客户端 DLL，不需要 Python，不执行 vgamepad 的安装器。来源、SHA256 与许可证随包保留。
- XInput 槽位是 0..3，并不等于游戏里的 P1/P2。其他连接中的手柄可能改变分配；请现场确认两只分别控制哪个角色。

## 一次性输入验收

1. 本机已按授权安装经过签名校验的官方 ViGEmBus 1.22.0，未重启；检查驱动可用即可，不要重复安装。
2. 导入 `local-plugins/artifacts/dungeons-input.zip` 并启用。关闭设置窗口后重开，在「工具配置」最底部找到「昔涟地下城输入测试」。启用本身不创建手柄。
3. 点「检查驱动」，可用后点「创建两只测试手柄」。请先切回面板再创建：初始化用一个单位的右摇杆值修正驱动初始报告，随即归零，不按按钮；Windows 确认两只手柄归零后才显示就绪。

   必须看到「两只手柄已创建」以及设备 ID / XInput 槽位。「测试手柄未连接」时没有可用输入会话；检查驱动、创建、停止按钮的反馈不代表已发送 LS。v0.1.1 在未连接时禁用发送/取消，并显示明确的前置步骤；创建失败的实际原因显示在面板通知中。

   v0.1.2 修正了首次状态查询的加载时序：实际设置页在 iframe 加载完成后才登记面板，旧版提前查询可能被忽略，导致系统手柄存在但面板一直显示「正在读取状态」。现在等待宿主 init 后才查询和轮询，加载期间不开放创建按钮；没有改动宿主、Chat、驱动或输入后端。

   v0.1.3 补上本机实际启动的 WindowsApps 精确路径。旧版只认可 XboxGames 路径，会将已在前台的初代误判为失焦。取消时现在记录当时的前台进程 ID、路径或读取错误；这些是动作取消时的快照，不代表你返回面板之后的前台。若游戏更新改变包路径，将继续拒绝输入并显示实际路径，需重新核验后更新白名单。
4. 从 Xbox 应用正常启动初代，选择离线游戏。使用新建/可用于测试的角色；本工具不复制、备份或改动存档。
5. 按游戏屏幕加入提示选择对应按钮（可能是按左摇杆 LS，也可能要其他按钮）。若需要初始化 P1，手动选择第一只并勾选明确确认；操作后该手柄回到中性。之后用第二只加入 P2、选择角色。任何时候都不要把游戏角色号直接当成 XInput 槽号。

   v0.1.4 提供菜单确认 A、返回 B、四向 D-pad 快捷按钮，共用当前手柄、按住时长和倒计时，不发送键盘 Enter/Esc。原始按键均已存在，后端未新增映射。角色选择中用方向键把焦点移到「完成」再发 A；返回可试 B。菜单用途标签参考常见 Xbox 导航，具体以本机游戏映射为准；战斗时 A/B 作用不同。Back 是 View 视图键，并非 B 返回键。
6. 面板选择第二只、向右、200 毫秒、5 秒，点「倒计时后发送一次」，在 5 秒内切回初代游戏。观察是否只有 P2 短移；同时用原生键鼠移动/攻击 P1，确认没有串台。
7. 测试 A/B/翻滚等对应按钮，先在营地或安全区域试。按钮意义以游戏当前映射为准，面板只显示原始 Xbox 按键。
8. 发送一次 1000 毫秒脉冲，在途中切出游戏：应立即释放；重新切回不得继续旧动作。测试 F12 停止与面板停止，结果应为已停止。
9. 点「断开并移除测试手柄」，仅删除本工具创建的两只设备。关闭插件同样清理；不重连、不重试、不重放。

成功标准：两名角色进入同一离线会话；P1 原生键鼠可用；第二只输入只控制 P2；失焦/停止/期限释放正确。任何一项不成立，先记录屏幕提示、槽位与结果，不继续开发自动战斗。

## 输入与退出保护

每次脉冲按住 50..1000ms，延迟 2..10 秒，只有一个待执行动作。第一只输入需要独立确认。实际执行前和执行中每约 15ms 核对初代前台路径；不激活窗口、不劫持键鼠。F12 只读取按下状态，不吞键。宿主每 500ms 发心跳，3 秒无心跳退出并移除设备；输入管道关闭也退出。普通断开先中性化再移除，宿主异常退出后由子进程心跳/管道与总线句柄关闭负责清理。

`sent` 只说明原始手柄报告发出并释放，不证明玩家加入、攻击命中或角色移动；这些须在游戏观察。已经发出的按键不能撤销其游戏效果，取消不会自动再试。

## 构建与验证

`node scripts/build-dungeons-input.mjs`：仅构建此插件，编译 x64 .NET 后端并运行无驱动策略测试。`npm.cmd test -- --run tests/dungeons-input.test.ts` 验证宿主管理和面板。缺驱动检查、策略与面板通过不代表本地双人已通过；真实虚拟设备、游戏双人须另验收。

v0.1.2 已通过 20 项 Vitest 测试和定向类型检查；额外使用实际设置页 `plugin-panels.ts`，在独立 Electron 中故意延迟 iframe 加载，验证首个状态查询在宿主登记后到达、轮询和面板调用恢复。修复前同一检查失败且宿主未收到任何面板调用；修复后的 8 项原生检查通过。此检查只探测驱动，没有创建额外手柄。

v0.1.3 的编译后 .NET 检查扩展到 25 项，包括已核验 WindowsApps 别名放行、其他包/版本/启动器/未知路径拒绝、取消时保留实际窗口诊断，以及读取失败释放已按下的模拟输入。`DungeonsInput.exe --foreground-status` 可只读查看实际窗口与精确白名单，不连接驱动、不创建手柄、不发送输入。游戏内 LS 加入和键鼠兼容仍需人工验收。

菜单导航参考：[Microsoft 游戏手柄导航命令](https://learn.microsoft.com/en-us/windows/uwp/gaming/gamepad-and-vibration#ui-navigation)。此文档说明通用导航约定，不代表已实测地下城每个菜单或自定义按键配置。

v0.1.4 已通过 26 项 Vitest 测试（包括六个菜单快捷按钮的原始手柄参数、倒计时、单次发送和禁用状态）、定向类型检查、25 项编译后 .NET 检查和 9 项实际设置页 Electron 检查。本轮未创建额外设备或发送游戏输入；后端和原生键鼠均未改动。现有版本也可在原始按键列表中选择 A/B/D-pad，无需为当前角色选择流程立刻更新插件。

v0.1.1 已通过 19 项 Vitest 宿主/面板测试、17 项编译后 .NET 输入策略检查和 10 项隐藏独立 Electron 原生验收（真实插件安装器、官方面板桥、客户端 DLL、驱动探测，以及真实会话中 LS 排队后立即取消、终态显示与断开）。取消发生在十秒倒计时内，确认未发送 LS。后端未修改；v0.1.0 的 14 项真实设备检查已确认两只句柄分别只影响自己的 XInput 槽、随即归零，并验证停止、心跳中断、管道关闭和进程结束后的设备移除，不启动游戏、不发送游戏动作按钮。安装前的缺驱动退出检查也已通过。此插件与测试的定向 TypeScript 检查通过；整个 local-plugins 检查被原有 real-history-ab / real-image-ab 测试的邻仓相对导入错误阻塞，未修改这些无关文件。

驱动已安装；早期独立设备测试结束后 XInput 连接状态恢复到测试前基线。用户随后反馈双人输入测试通过；新增营地跟随的自动检查仍不能替代游戏内验收。
