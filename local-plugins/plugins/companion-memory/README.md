# 独立记忆引擎 0.53.0

0.53.0 为原生 Chat 动态记忆上下文声明稳定优先级，使其固定处于生活日程之后、WorldBook 之前，不再
依赖两个插件的扫描与启用顺序。旧宿主若不支持 `priority` 仍可加载插件，但只能退回注册顺序。

0.52.0 增加默认关闭、单独授权的短期对话连续性。启用后，每个明确冻结为 companion 且成功落盘
的桌面 Chat 回合额外调用一次宿主当前模型，只接受带本轮用户逐字证据的 `short_term`（14 天）和
`open_loop`（3 天）；只允许关闭本轮查询实际召回的至多 3 条旧话题。状态按会话隔离并只写插件私有
存储；后续同会话按相关度最多注入 3 条，明确“继续／上次”等回忆意图可以恢复已过期候选。功能不依赖
普通记忆回复注入开关，但依赖成功回合读取；原生后端、渠道与其他模式均不抽取、不注入。可选
Embedding 开启时，新连续性摘要和当前查询可能发送到用户配置的服务；失败时退回本地词面与时近度。
“形成于”时间使用宿主提供的只读 IANA 聊天时区；插件不读取城市、坐标或宿主私有配置。

0.51.0 补齐伴聊后端的近期关系线索。它复用插件已经保存的成功伴聊轮次，按本地版相同的确定性
情绪、边界偏好、当日摘要和下一轮回应提示规则派生上下文；不复制第二份聊天正文、不新增模型调用，
也不建立另一套关系数据库。该上下文只随已启用的伴聊记忆 Provider 注入。宿主轮次事件同时增加
开始时冻结的 `chatBackend` 元数据；记忆摄取只接受明确为 `companion` 的成功桌面 Chat，明确
`native` 或旧宿主缺少该字段时均保守跳过，防止两种后端的历史混写。

0.50.0 将原本彼此独立的近似空闲梦境、容量瘦身和压缩建议合并为一个有序周期：先按本地版
300/800 容量与 `weight × 30 天时近度` 规则提交插件私有状态降级，再只用本周期降级的最多
20 条记忆生成叙事，最后对 aging 向量按 0.82 阈值生成最多 5 组压缩复核。叙事保存和压缩应用
继续使用各自独立授权；安全压缩仍要求 0.80 置信度、完整覆盖和提交前快照核对。完整周期启用时，
独立的每 20 轮压缩计时暂停并清零，关闭周期后恢复，避免同一候选被两套调度重复处理。界面显示
当前阶段、最近各阶段数量和失败阶段；用户活动仍会取消尚未完成的模型请求。

0.49.0 将后台压缩的应用方式明确为“生成建议后手动确认”与“符合安全条件时自动压缩”二选一，
继续复用原有授权存储，不迁移或覆写记忆库。自动模式的置信度下限由 0.90 调整为 0.80；至少
3 条 aging、非置顶、非摘要来源、完整覆盖确认、提交前记忆与证据快照复核及严格撤销等其他条件
均保持不变。界面顶部展示最近 3 个已应用或已撤销的压缩组，并为新记录保存实际应用／撤销时间；
旧记录没有这些时间字段时继续兼容，显示其原有记录时间。

0.48.0 为近似空闲梦境增加第二重、默认关闭的自动保存授权。后台梦境仍须先显式启用；自动保存只
采用刚生成且已通过既有来源快照、aging／非置顶约束和长度校验的叙事，不修改或归档来源记忆，
继续保留严格撤销，是否注入聊天仍由独立开关控制。关闭后台梦境会同步关闭自动保存，避免隐藏授权
在以后恢复。只启用后台梦境时仍保持原有“生成待确认草稿”行为。

0.47.0 将唯一的记忆提取批次统一调整为每会话当前 10 轮可写内容，并附带同一会话紧邻的最多
2 轮已处理上下文。独立聊天的手动提取与上游原生 Chat 自动提取继续共用 `maintain` 实现；不足
10 轮时保留队列，不调用模型，也不跨会话拼批。

0.46.0 增加严格人工确认的 archived 冷召回。它只在普通 active/aging 词面或分面检索没有明确
命中时，于插件窗口本地列出最多 8 条仍在有效期内、且未被取代或合并的归档候选，并展示来源时间、
原话提示和有限关联证据。预检不进入正常检索、Prompt Provider 或聊天注入，不调用模型，也不更新
DMAE、生命周期注入时间、weight 或访问统计。用户明确选择后才把对应插件私有条目恢复为 active；
恢复绑定记忆 revision、查询与完整候选快照哈希，过期即拒绝，并保留可严格撤销的 archived 快照。
恢复后的新语义索引行为仍受既有、单独授权的 Embedding 设置控制。

既可与 companion-chat 联动，也可通过官方 API 接入上游原生桌面聊天。默认不读取宿主
memory.json、RAG 或原会话，任何情况下都不写这些源文件。当前能力：独立对话档案、词面检索、
每会话前 2 轮上下文 + 最早 10 轮待提取、逐字证据校验、
原始时间、相同摘要去重、失败保留队列、独立浏览窗口。

0.45.0 使用宿主 `host:prompt:accepted` 消费回执：只有记忆 Provider 的完整内容确实进入最终插件
上下文，并且同一 runId 最终成功落盘时，才提交本轮 DMAE 与生命周期命中。单项截断、总预算截断、
Provider 超时、模型失败、取消或落盘失败都不推进状态。旧宿主会忽略声明式回执开关，但仍按原字符串
接口注入记忆；此时保守地不提交消费副作用，不会因兼容降级误更新激活值。

0.44.0 仅在送入提取、来源核验和历史检索的派生副本中清洗 assistant 的隐藏思考标签，
不改原消息。原生 Prompt Provider 按画像、置顶/当前命中、DMAE、历史证据、梦境的顺序
选择完整块，不再截断半条证据；只有进入本次插件输出的记忆 ID 才推进 DMAE 与生命周期命中。
0.45.0 已补齐宿主最终插件上下文的接收确认；它仍不声称模型服务端一定完成推理，最终副作用还需
与宿主确认落盘的成功终态配对。

0.43.2 将“原生回复注入”限定为桌面 Chat。外部渠道虽然也可能使用 Chat 模式，但其请求
带有 `channel`，现在不会检索或收到插件私有记忆；此前依赖渠道记忆注入的用法会改变。
Moments 发帖仍由单独的默认关闭开关控制，不受这次改动影响。

0.43.1 将原生会话读取、自动维护/复核/压缩/生命周期/梦境计时及记忆提示词注入限定为
桌面 Chat，不再由 Work/Code/Learn 触发。升级前已排队且缺少 mode 的旧轮次会通过官方只读
会话列表核验：非 Chat 跳过，无法核验则保留待处理并报读取错误，不会猜测模式后摄取。

0.43.0 收紧画像反思的证据边界：只把逐字原话可与插件私有用户轮次或已核验历史消息证据对上的
非摘要、未编辑、当前可检索 L2 送给模型；未核验旧条目不再参与。反思候选保存来源条目快照、
模型自报置信度与理由，人工采用时重新核对来源和原画像，采用后可在两者未变化时严格撤销。
后台计数只接受成功的桌面 Chat 轮次，不计 Work/Code/Learn。没有开放自动采用：模型自报
高置信和文字包含关系都不足以证明新画像的时态、否定和主体正确。

0.42.0 增加默认关闭的每 20 轮 L0/L1 画像反思候选。与本地版只把当前画像发给模型并以
0.60 阈值直接覆盖不同，插件只发送当前画像和最多 30 条较新、当前可检索且带原话或已保存证据的
插件私有 L2。模型只能替换已有字段，最多提出 8 条置信度至少 0.80 的待确认候选；无效来源、较旧
来源、空字段新增和锁定的 L0 均不落候选。用户采用前仍检查原画像快照，后台不会直接覆盖画像。

0.41.0 为每 20 轮后台压缩增加第二重、默认关闭的自动应用授权。自动路径只接受至少 3 条
aging、非置顶、非摘要来源，且模型明确给出至少 0.80 的置信度并确认总结完整覆盖全部来源的
时间变化、对象、否定、计划与结果。应用前仍逐项核对记忆和证据快照，并沿用一次写入与严格撤销；
两条来源、旧格式结果、低置信、覆盖未确认或任何已变化建议均保持 pending。关闭后台压缩会同步
关闭自动应用，避免隐藏授权在以后恢复。手动 2 至 5 条压缩流程保持兼容。

0.40.0 为每 5 轮后台 Resolver 增加第二重、默认关闭的自动应用授权。只有置信度至少 0.90、
无需澄清的 unrelated/context_difference 无变更计划会自动关闭；preference_evolution 还必须创建
完整双来源总结，且两侧都明确转为 superseded/merged，才会原子应用。direct_conflict、uncertain、
低置信、需询问用户及其他状态组合始终保持 pending。关闭后台复核会同步关闭自动应用；重启只恢复
用户仍明确保留的双重授权。所有实际变更继续使用 0.39.0 的快照事务和严格撤销，不自动删除证据。

0.39.0 将 L2 双条复核扩展为兼容本地版语义的结构化 Resolver 计划：区分 unrelated、
context_difference、preference_evolution、direct_conflict 和 uncertain，保存置信度、澄清标记、
可选完整总结及两侧目标状态。模型仍只提出计划；uncertain 或要求澄清的结果不能携带变更，
superseded/merged 必须指向同时创建的双来源总结。用户确认后一次写入，原条目和证据不删除；
两侧、新总结或证据未发生后续变化时可严格撤销。旧版 verdict 记录继续只读兼容，自动应用尚未开放。

0.38.0 在 0.37.0 的插件私有 weight 基础上开放容量计划的一次性确认执行：预检同时绑定记忆版本、
生命周期版本和候选签名，过期计划整体拒绝；每组最多处理 100 条，只改变插件私有状态，一次写入并
分别保存 aging/archived 可撤销快照。严重超限时同一 active 条目可在一笔事务中先降为 aging 再归档，
撤销仍须按归档、老化顺序逐层恢复。没有后台自动容量提交，也不删除正文或证据。

0.37.0 把本地版 weight 的必要状态迁入插件私有生命周期存储：初值按 0 处理，每次实际注入 +1，
范围限制为 0 至 100；手动搜索、预检和原文读取不会更新。启用生命周期自动执行后，每日对当前

`weight × 30 天时近度` 从低到高选择非置顶候选；预检不改变状态，执行需逐次确认。

本地版 weight 字段；0.37.0 已在不改记忆正文结构的前提下补入插件私有权重和只读容量预检，
0.38.0 再补入逐次确认、可撤销的容量执行事务。

0.26.0 使每次人工生命周期批量变更可严格撤销。active→aging 或 aging→archived 与全部来源条目
快照在同一次 `memory-state` 提交中保存；撤销前逐条核对当前记录是否仍等于“原快照＋目标状态”。
只有全部未发生后续编辑、置顶或状态变化时才原样恢复，否则整体拒绝，避免旧操作覆盖新数据。
最近 200 次变更记录留在插件私有记忆中；撤销不改生命周期注入统计或宿主数据。

同版补正梦境容量记录：保存第 9 段叙事时，最旧叙事仍按 8 段上限淘汰，其对应复核明确转为
`evicted`，界面不再显示注定失败的撤销按钮。来源记忆及其证据不受淘汰影响。
复核日志裁剪也始终优先保留当前 8 段叙事所引用的复核，再用剩余槽位保留最新普通草稿，避免
大量关闭草稿挤掉仍在使用的来源关系并造成下次加载失败。

同版还修正维护候选的幂等性：已保存或已关闭的关系在后续本地扫描中直接排除；候选为空时没有
提交入口，重复扫描不写收件箱 revision，也不会让已处理关系反复出现。

不返回密钥。启用后每次检索只发送当前查询文本，不发送记忆库；固定测试按钮只发送合成英文文本。
向量源只允许绝对路径 memory-store.json 普通文件，预检返回固定聚合和 SHA-256；正式导入再次核对
哈希，只复制 source=user_memory 且 l2Id 能关联到已导入 L2 的数值向量，不复制 text 或 chat_history。
导入前保存空索引备份，已有索引/备份拒绝覆盖；维度不一致时明确失败，不静默退回伪语义结果。
新提取或手动编辑的记忆只有在用户另行启用 0.14.0 的正文外发授权后才会生成向量；否则仍走
词面/facets 召回。尚未在真实插件库执行导入或发起真实 Embedding 请求。

这是可运行的迁移基座；Reranker、DMAE、人工可撤销压缩、人工生命周期事务、维护候选收件箱
与人工梦境反思已有保守插件实现。后台候选复核、压缩建议、每日生命周期计数和近似空闲梦境
草稿也已实现；Resolver、压缩、生命周期与梦境叙事各自提供第二重且默认关闭的自动应用授权。
官方 API 仍不提供系统级真实空闲状态。
词面基线不应被用于判断原系统的语义召回效果。

0.3.0 增加可选模型辅助查询扩展。记忆窗口勾选并确认后，聊天检索与手动搜索每次额外
请求当前宿主官方模型服务，只发送当前查询、不发送整个记忆库。模型最多返回 3 个扩展短语，
原查询权重高于扩展词；最终注入仍来自本插件已有画像、记忆和历史，不注入模型生成的短语。
默认关闭；开关只存本插件 query-expansion.json。启用会增加费用和延迟，失败会明确报错，
可关闭恢复纯词面检索。此方案不是 Embedding/Reranker，也不能保证同义表达一定召回。

写入仅限宿主分配的插件私有目录（包括自身 `memory-state.json`）；密钥不属于本插件。
加载插件不调用模型、不自动扫描原用户数据；旧记忆预检仅在用户确认后只读打开指定文件。查询扩展仅在用户开启后随检索调用；提取由聊天窗口确认触发，请求使用当前宿主官方模型服务，
会发送本插件内待处理对话。插件事件不是安全隔离通道，只应与可信插件同宿主运行。

停用后拒绝迟到提取结果并保留未完成队列。已通过上游真实 PluginManager 的隔离加载与合成消息
联动测试，但未启动完整 Electron 宿主，也未发送真实历史到模型。

2026-09-13 本地接入补充：旧记忆导入仍默认标为 `legacy-unverified`。若用户已独立核验旧库，
可在导入窗口显式声明；插件将源 SHA-256 与声明一起保存，并用独立的
`legacy-user-attested` 标签标注 L0/L1、L2 和 evidence，不伪造未保存的消息 ID，也不把这类
来源当作机器可重找的反思证据。只读预检另显示旧访问统计和 DMAE 状态是否完整兼容；
仅用户再次勾选时，导入才把它们作为初始基线与记忆一起写入同一个插件私有状态键。
DMAE 与生命周期功能开关仍保持原样、不会因导入自动开启。此机制未完成真实快照导入验收，
也不涵盖旧冲突/反思日志、待处理轮次与独立向量索引，不能宣称完整复刻。
